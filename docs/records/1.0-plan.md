# Gangline 1.0 — lexicon and surface plan

> Status: Landed at `70df88a` on 2026-08-08; retained as a dated
> implementation record.

Operator-approved 2026-08-07. This document is the charter source for the 1.0
arc, which runs after the lead-ergonomics release ships. 1.0 is the stability
promise: the names below are the names the config file, env vars, and docs
commit to.

## Ontology (documented in README at 1.0)

A **dog** (model instance) wears a **harness** (the native CLI runtime —
Claude Code, Codex, opencode, Pi), fitted to the **gangline** (the tmux
session) by its **collar** (the per-harness adapter), driven by the
**musher** (the operator). The musher's adopted window is conventionally the
**lead**; the lead is coordination convention, not a core concept, and core
gains no lead machinery.

"Dog" is the documented noun for a hitched agent. "Harness" refers only to
the runtime, never to the hitched instance.

## Renames

| Current | 1.0 | Reason |
|---|---|---|
| profile, `profiles/`, `gang profiles`, `GANG_PROFILE`, `GANG_PROFILES`, config keys | collar, `collars/`, `gang collars`, `GANG_COLLAR`, `GANG_COLLARS` | "Profile" is overloaded everywhere; a collar is literally identity + attachment point, which is the adapter's whole job. |
| `gang cutoff` | `gang curfew` | Takes wall-clock `HH:MM` and durations; "timeout" implies per-operation, "cutoff" was a stretch. Curfew is themed AND instantly guessable: everything is home and stopped by curfew. |
| `busy (tight tug)` / `idle (slack tug)` / `occupied (…)` / indeterminate | `-busy-` / `~idle~` / `!occupied!` / `?unknown?` | Subtle glyph family: `-` a tight line, `~` a slack one, `!` a snagged line, `?` a line out of sight. Words still carry the meaning; the glyphs are the easter egg. "Unknown" replaces "indeterminate". |

Old names deprecate as announced aliases per the published-name precedent in
DECISIONS.md; the config file and env accept both for one major cycle.

## Window-name state glyphs

Gang-managed tmux windows carry the wrapped state glyph in the window name
(`-pii-impl-`, `~ergo-impl~`) so the tmux status bar shows team state at a
glance. Contract:

- The glyph is **last-witnessed** state, updated at gang's existing
  observation points and hook events — never by a patrol. Between
  observations it can be stale; `gang roster` remains the live-computed
  truth. This limitation is documented, not engineered around.
- Addressing always uses the bare name; gang strips glyphs on every lookup.
  `gang send --to pii-impl` never changes.
- tmux appends its own flags after the name, so the last-active window
  renders as `3:-name--`; the trailing pair is tmux's. Documented, not
  fought.

## Deliberately unthemed

`up down send flush interrupt compact capture status attach composer config
notify context usage adopt hitch drop roster` keep their names: they are
operational surface a stranger must guess correctly on the first try, and
hitch/drop/roster/gangline already carry the theme where it is literal.
Rejected themings, recorded so they stay rejected: envelope→tag (git-tag
collision), held→snubbed (product-name collision with snubline), stall→balk
(obscure). The bar for a themed name is that it is ALSO the clearest name;
only collar and curfew clear it.
