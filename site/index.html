gangline

A gangline is the line that connects every dog's harness to the sled.

demo start what it does long sessions github

Gangline runs Claude Code, Codex, OpenCode, and Pi as named windows in one tmux session, so they can hand each other work by name and you can watch the whole thing happen.

curl -fsSL https://raw.githubusercontent.com/adambiggs/gangline/main/install.sh | sh

Demo

Compose with gang talk, watch the real harnesses build with gang attach, then run their result. Nothing here is re-enacted.

Start

First run each native harness directly to finish its normal onboarding, sign-in, and repo-trust prompts; Gangline never answers security choices. Then open a team in the repo the agents should work in. gang up starts a Claude Code lead and drops you into its window.

cd ~/your/repo
gang up -c claude-code -m sonnet -e high

Codex may show a separate hook-review prompt on its first Gangline hitch: running Codex alone cannot clear it because Gangline adds those hooks at launch, and a changed hook path or command can raise the review again. If hitch reports a first-run prompt, run gang attach from another operator terminal, select the named worker window, and answer it there. The original hitch will then finish. Ask the harness for a current Codex model and one of the efforts listed beside it — the later example reuses the two variables you set here — then add the agent and give it something to do.

gang models -c codex
read -r -p "Codex model: " CODEX_MODEL
read -r -p "Codex effort: " CODEX_EFFORT
gang hitch worker -c codex -d "$PWD" -m "$CODEX_MODEL" -e "$CODEX_EFFORT"

gang send --to worker --from operator --stdin <<'TASK'
Fix the failing parser test and report the proof.
TASK

gang roster

What it does

  • Delivers work by name. A message is typed into that agent's own terminal, signed with the sender's name. It reads like anything else you would type there — no side channel, no protocol for anyone to learn.
  • Tells you what actually happened. A message is reported delivered only once Gangline has seen it land and be submitted, never on the strength of having typed it. Where a harness lets it read the input box, it will not type over a line you half finished. What it reports when a message does not land, and what makes it refuse, is in the reference.
  • Lets you read over their shoulder. Every agent is a real tmux window. gang attach to watch one work, gang roster to see who is busy and who is waiting.
  • Adds and removes agents mid-run. A fully specified gang hitch opens another harness on the same repo, and gang drop reviewer closes it again.
  • Gets a run through the night. An agent watching its context fill can compact at a checkpoint it chooses and carry on, and one that spends its provider quota can be woken when that quota resets.

What it deliberately isn't: there is no task graph, no supervisor, no daemon, and no database. Gangline connects native agents; it does not manage them. It hands out no work, chases nobody, enforces no deadline, and never answers a permission prompt or loosens a harness's sandbox. Each agent keeps the terminal, tools, permissions, and subscription it already had.

It is also not a replacement for whatever subagents your harness spawns on its own — Gangline operates one level up. A subagent is created and owned by a single harness session, and that ownership is what makes it one. Gangline works between sessions instead: every agent in a team is a separate top-level process running the harness's ordinary CLI in its own tmux window, and one team can put Claude Code, Codex, OpenCode, and Pi side by side. That is a difference in architecture; what each command does and refuses is in the reference.

Long sessions

A team that runs for hours hits two walls: the context window and the provider limit. Gangline helps with both without taking the decision away from the agent.

Context lights tell an agent once when it crosses yellow and once when it crosses red. What it does about that is its own call: when it wants the room back it runs gang compact, which fires the harness's real compaction command — the same one you would type yourself. Each collar sizes those edges for the model you hitched, so a team mixing harnesses gets working lights with nothing configured:

gang hitch worker -c codex -m "$CODEX_MODEL" -e "$CODEX_EFFORT"

Set them yourself for one agent, or for the team, when you want edges of your own — high, but below the point where the harness would compact on its own:

gang hitch worker -c codex -m "$CODEX_MODEL" -e "$CODEX_EFFORT" --lights 50%,80%

The provider limit is the other wall. When an agent's own usage crosses the percentage you named, Gangline can set a one-shot wake for that window's reset and send the agent back to work when it fires — so a team can carry on across a limit with nobody at the keyboard:

GANG_AUTO_RESUME="97%" gang hitch worker -c claude-code -m sonnet -e high

If you want the team to know the clock, declare one curfew. Yellow lands halfway through the span and red after four-fifths, and agents whose harness reports its own turn boundaries are told once at each edge. Nothing stops automatically.

gang curfew 2h

One Bash script over tmux. State dies with its window or team.
