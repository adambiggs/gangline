Gangline

Many CLI agents. One coordinated team.

demo· install· how it works· fit· commands· links

Gangline is the substrate under a long-running, multi-harness agent team. Claude Code, Codex, opencode and Pi run as named tmux windows; gang starts them, verifies attributed delivery into their input boxes, reports observable state, and warns where a profile can establish context use.

You decide who does what and in what order. Gangline is a Bash CLI over tmux: no orchestrator, daemon, message bus, database, or harness plugin, and gang exits after every command.

Live demo

 tmux: gangline

One message to a Claude Code lead: it hitches a Codex worker, waits for the work, then hitches an opencode reviewer to check it. Real harnesses, real subscriptions, unedited except for cuts through the waiting.

 tmux: gangline
$ cd ~/my/repo && gang up
# detach with Ctrl-b d, then use another shell
$ gang hitch worker -p codex -r worker
hitched worker (codex) in ~/my/repo — watch: gang attach
briefed worker as worker
$ gang send worker --from lead --stdin <<'MESSAGE'
read the failing test in ci and fix it
MESSAGE
delivered to worker as [gang:lead] (verified in pane, submitted)
$ gang roster

Install

$ curl -fsSL https://raw.githubusercontent.com/adambiggs/gangline/main/install.sh | sh

Needs git, tmux ≥ 2.6 and python3. The installer clones Gangline, links gang into your path, and updates the clone when run again. Read the script first or follow the manual path.

Unattended permissions: configure them in the harness; Gangline does not answer prompts. Read the harness-specific cautions.

Isolation: agents on one host share what their account and harness configuration allow. Use a container, VM, or separate account when you need a security boundary. Read the boundary.

How it works

Agents are tmux windows.
The window name is the agent's identity and command handle. Attach and you are in the harness's native TUI, with its pane and keystrokes intact.
Messages and state are measured.
Every send is attributed and verified through pane capture. Unreadable, unchanged, occupied, and otherwise uncertain results fail or remain explicit; Gangline does not turn missing evidence into a healthy state.
Renewal is a cycle.
Gangline measures context, warns the agent, and gang cycle replaces the context at an agent-authored checkpoint. Continuation state is reviewed against the live team task ledger, not accepted as free-form resume prose; the operator workflow owns the exact procedure.
Profiles and role briefs are replaceable.
A profile declares how Gangline launches and observes a harness; a role says what an agent is for. GANG_PROFILES and GANG_ROLES let you shadow either without patching Gangline.

Fit

Gangline fits when
  • you want different CLI harnesses in one inspectable tmux session;
  • the operator and role briefs should own the workflow;
  • work benefits from verified delivery, explicit uncertainty, and measured context renewal over time.
Gangline does not fit when
  • you need the substrate to create separate worktrees or enforce a security boundary;
  • you need a dashboard, notifications, history after a window dies, or automatic restart;
  • you need Gangline itself to own task graphs, retries, supervision, or deterministic API orchestration.

Gangline also remains version-fragile where it observes terminal chrome. gang vet reports profile drift; it does not pretend to repair it. The README names better-fitting alternatives.

Minimal command path

gang up
Hitch a briefed lead in the current directory and attach.
gang hitch <name> -p <profile> -r <role>
Add a named teammate.
gang send <name> --from <sender> --stdin
Send an attributed, pane-verified message read from stdin.
gang roster
Read every agent's observable state and any context readout the profile can establish.
gang cycle <name>
Renew one agent at a reviewed checkpoint. Follow the continuation workflow before using it; continuation is not generic stdin.
gang drop <name> / gang down
End one window / the whole team. Use drop for routine release.
